# Building an Evaluation Dataset from a PDF with Easy Dataset

A step-by-step guide to turning an existing PDF into a question-and-answer **evaluation dataset**, exported as a CSV with the columns:

```
test,question,expected_answer,source_doc,category
```

The workflow has two stages:

1. **Generate** the Q&A pairs from your PDF inside [Easy Dataset](https://github.com/ConardLi/easy-dataset).
2. **Convert** the Easy Dataset export into the target CSV using the helper script `easy_dataset_to_eval_csv.py`.

---

## 1. Why two stages?

Easy Dataset does the hard part (parsing the PDF, chunking, generating questions, generating answers, and auto-tagging categories), but its built-in exports are **Alpaca / ShareGPT** in **JSON or JSONL** — these are fine-tuning formats, not a CSV with your columns.

There is one important catch: the Alpaca and ShareGPT formats keep only the question and answer. They **strip the category label and the source chunk**. To keep `category` and `source_doc`, either export the **raw dataset** (which retains the label and chunk name) or pass fallback values to the converter on the command line.

| Your CSV column   | Comes from (Easy Dataset)                          | If missing in export        |
| ----------------- | -------------------------------------------------- | --------------------------- |
| `test`            | generated by the converter (sequential ID)         | always generated            |
| `question`        | the generated question                             | required — row skipped if empty |
| `expected_answer` | the generated answer                               | left blank                  |
| `source_doc`      | chunk name / source file in the raw export         | falls back to `--source-doc` |
| `category`        | the Domain Label Tree label                        | falls back to `--category-default` |

---

## 2. Prerequisites

- Your PDF document.
- An LLM API key. Easy Dataset works with any **OpenAI-compatible** endpoint: OpenAI, OpenRouter, MiniMax, Zhipu AI, Alibaba Bailian, or a local model via **Ollama**. For PDF parsing it can also use a vision model such as Gemini or Claude.
- Python 3.8+ to run the converter script.
- One of: the Easy Dataset desktop client, Node.js (for the npm install), or Docker.

---

## 3. Install and run Easy Dataset

Pick whichever is easiest for you. After it starts, open `http://localhost:1717` in your browser.

### Option A — Desktop client (no terminal)
Download the installer for Windows, macOS, or Linux from the [releases page](https://github.com/ConardLi/easy-dataset/releases/latest) and run it.

### Option B — npm
```bash
git clone https://github.com/ConardLi/easy-dataset.git
cd easy-dataset
npm install
npm run build
npm run start
```

### Option C — Docker
```bash
git clone https://github.com/ConardLi/easy-dataset.git
cd easy-dataset
docker-compose up -d
```

> Mount the `local-db` and `prisma` folders (the default `docker-compose.yml` already does this) so your project data persists between restarts.

---

## 4. Configure your model

1. Open **Settings → Model Configuration**.
2. Add a provider and paste your API key (or point it at your local Ollama endpoint).
3. Set a default model for generation. A capable instruction-following model gives better questions and answers.

---

## 5. Create the project and import the PDF

1. Create a **new project**.
2. Go to **Documents** (or **Text Split / Literature Processing**) and **upload your PDF**.
3. Easy Dataset extracts the text. If your PDF is scanned or image-heavy, enable a **vision model** for parsing.

---

## 6. Split the text into chunks

1. Choose a splitting strategy — by Markdown structure, recursive separators, or fixed length.
2. Tune the chunk size: smaller chunks give more focused, granular questions; larger chunks give broader ones.
3. Review the visual segmentation and adjust boundaries if needed. **Each chunk becomes the `source_doc` reference** for the questions generated from it.

---

## 7. Build the Domain Label Tree (your categories)

1. Open the **Domain Label Tree** (sometimes shown as "tags" or "labels").
2. Let Easy Dataset auto-generate the tree from the document structure, then edit it.
3. These labels populate the **`category`** column. Keep the set small and meaningful (for example: `Eligibility`, `Pricing`, `Governance`, `Risk`) so your evaluation set groups cleanly.

In Easy Dataset you don't trigger it from a separate "generate" button — it's created automatically. After text chunking is completed, the platform calls a large model to automatically establish a domain tag tree based on the document data. So the trigger is finishing the chunking step on your PDF. easy-dataset
To see and edit it, go into your project's Documents / literature processing section (the same area where you uploaded and split the PDF) and switch to the Domain Tree tab. There you'll see the domain tree the AI analyzed from the document, alongside the original table of contents extracted from it. easy-dataset
A couple of things worth knowing:

In the later question- and dataset-generation steps, Easy Dataset builds on this tree and maps each generated question and dataset entry to a domain tag — that tag is what ends up as your category column. easy-dataset
If the AI tree has gaps or inaccuracies, you can add, modify, or delete tags directly, and it's recommended to confirm the tree before generating questions. Fixing it here keeps your categories clean later. easy-dataset

So the order is: upload PDF → split into chunks → the tree auto-builds → open the Domain Tree tab to review/edit → then generate questions and answers.

## 8. Generate questions

1. Open **Questions** and run **batch generation** across your chunks.
2. Optionally edit the question template / prompt to control style (factual, scenario-based, etc.).
3. Review and delete weak or duplicate questions before generating answers — quality here drives the quality of your whole eval set.

---

## 9. Generate answers (the expected answers)

1. Open **Datasets** and run **answer generation**.
2. Easy Dataset produces an answer (optionally with chain-of-thought) for each question. The answer is your **`expected_answer`**.
3. Spot-check answers against the source PDF. For an *evaluation* set, the expected answers must be correct — they are your ground truth.

---

## 10. Using the dedicated evaluation mode (v1.7.0+)

Easy Dataset 1.7.0 and later include an **evaluation / test-set** mode built specifically for this use case. It can generate several question types:

- true / false
- single-choice
- multiple-choice
- **short-answer**
- **open-ended**

**Recommendation:** for a CSV with a free-text `expected_answer`, use **short-answer** or **open-ended** question types. The choice-based types store the answer as an option key (for example `B`), which does not map cleanly to a free-text expected answer without extra processing.

This mode also offers automated **Judge Model** scoring and a **human blind test (Arena)** for comparing models once your test set exists — useful after you have the CSV.

---

## 11. Export the dataset

1. Open **Export**.
2. **File type:** JSON or JSONL (both are supported by the converter).
3. **Format / style:**
   - **Best:** the **raw / original dataset** export, because it keeps the `label` (category) and `chunkName` (source) fields.
   - **Also works:** Alpaca or ShareGPT — but these drop category and source, so you must supply `--source-doc` and `--category-default` when converting.
4. Save the exported file somewhere you can find it.

---

## 12. Convert the export to your CSV

Run the converter script. It auto-detects raw, Alpaca, and ShareGPT shapes (JSON or JSONL) and writes exactly `test,question,expected_answer,source_doc,category`.

**Raw export** (category and source come straight from the file):
```bash
python easy_dataset_to_eval_csv.py export.json -o eval.csv --id-prefix test_ --pad 4
```

**Alpaca / ShareGPT export** (supply fallbacks, since metadata is stripped):
```bash
python easy_dataset_to_eval_csv.py export.jsonl -o eval.csv \
    --source-doc mydoc.pdf --category-default lending --id-prefix test_ --pad 4
```

### Command-line options

| Option               | Purpose                                                        | Default              |
| -------------------- | -------------------------------------------------------------- | -------------------- |
| `input`              | Path to the Easy Dataset export (`.json` or `.jsonl`)          | (required)           |
| `-o`, `--output`     | Output CSV path                                                | `eval_dataset.csv`   |
| `--source-doc`       | Fallback `source_doc` when the export has none                 | the input filename   |
| `--category-default` | Fallback `category` when no label is present                   | `general`            |
| `--id-prefix`        | Prefix for the test ID, e.g. `test_` → `test_0001`             | (none)               |
| `--start-index`      | First test ID number                                           | `1`                  |
| `--pad`              | Zero-pad width for numeric IDs (`4` → `0001`); `0` = no padding | `0`                  |

### Example output
```
test,question,expected_answer,source_doc,category
test_0001,What is the maximum loan-to-value ratio?,80% for residential property.,policy.pdf-chunk-3,Lending Policy
test_0002,Who approves exceptions?,The credit committee.,policy.pdf-chunk-7,Governance
```

---

## 13. Validate the result

- Open the CSV and confirm the header row is `test,question,expected_answer,source_doc,category`.
- Check that `test` IDs are unique and sequential.
- Confirm `category` values match your label tree (not the `general` fallback) — if everything says `general`, you exported Alpaca/ShareGPT instead of the raw dataset.
- Spot-check a few `expected_answer` values against the PDF for correctness.
- Make sure no rows have an empty `question` (the converter skips empties, but verify the count matches expectations).

---

## 14. Tips and troubleshooting

- **All categories show `general`** → you exported Alpaca or ShareGPT. Re-export as the raw dataset, or pass `--category-default` per export and split your exports by category.
- **`source_doc` shows the JSON filename instead of a chunk** → same cause; the format stripped the chunk metadata. Use the raw export or pass `--source-doc`.
- **Answers look like option keys (`A`, `C`)** → you used a choice-based question type. Regenerate with short-answer or open-ended, or post-process to expand the option text.
- **Commas or quotes in questions/answers** → handled automatically; the script writes a properly quoted CSV.
- **Non-English content** → the converter is UTF-8 throughout; open the CSV as UTF-8 (in Excel, use *Data → From Text/CSV* and pick UTF-8).
- **Large PDFs** → split generation into batches and review each batch; it keeps quality high and makes token costs visible in the resource dashboard.

---

## 15. Quick reference: the whole flow

1. Install/run Easy Dataset → `http://localhost:1717`
2. Configure model → create project → upload PDF
3. Split into chunks
4. Build Domain Label Tree (categories)
5. Generate questions → generate answers (short-answer / open-ended)
6. Export as **raw** JSON/JSONL (keeps category + source)
7. `python easy_dataset_to_eval_csv.py export.json -o eval.csv --id-prefix test_ --pad 4`
8. Validate the CSV
