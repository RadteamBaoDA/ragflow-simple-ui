# Manage Customer Communication

## Purpose

Produce a clear customer communication or decision record.

## Task responsibility

Own delivery governance, coordination, customer alignment, and project controls. Do not invent contractual commitments, technical approvals, test evidence, or customer acceptance.

## Reference routing

Classify the subtype before detailed work. Read only the matching reference; combine references only when the request spans multiple observable subtypes.

- Read [Routine status update](references/status-update.md) when the audience needs a concise periodic delivery view.
- Read [Steering committee](references/steering-committee.md) when executive governance must decide or unblock material matters.
- Read [Escalation](references/escalation.md) when a threshold breach needs timely management action.

## Core method

1. Resolve **Audience and Purpose** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
2. Resolve **Current Status** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
3. Derive **Decisions Required** from explicit criteria; state conditions, dissent, and decision authority.
4. Resolve **Commitments and Owners** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
5. Analyze **Risks and Escalations** by trigger, exposure, consequence, control, and residual state.
6. Resolve **Next Checkpoint** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
7. Reconcile contradictions and state unresolved evidence, decision, and ownership gaps.

## Quality checks

- Tie commitments to accountable owners, dates, dependencies, estimates, and approval evidence.
- Keep coordination status distinct from specialist quality, security, and production gates.
- Confirm proposed changes are separated from approved baseline content.
- Confirm acceptance, approval, test, release, and customer decisions are claimed only with evidence.
