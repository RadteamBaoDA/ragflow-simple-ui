# Track Status and Milestones

## Purpose

Produce an evidence-backed project status report.

## Task responsibility

Own delivery governance, coordination, customer alignment, and project controls. Do not invent contractual commitments, technical approvals, test evidence, or customer acceptance.

## Core method

1. Resolve **Overall Health** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
2. Build **Milestone Progress** from dependencies, capacity, uncertainty, constraints, and reviewable assumptions.
3. Build **Plan Versus Actual** from dependencies, capacity, uncertainty, constraints, and reviewable assumptions.
4. Resolve **Delivery Forecast** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
5. Derive **Decisions Needed** from explicit criteria; state conditions, dissent, and decision authority.
6. Build **Next-period Plan** from dependencies, capacity, uncertainty, constraints, and reviewable assumptions.
7. Reconcile contradictions and state unresolved evidence, decision, and ownership gaps.

## Quality checks

- Tie commitments to accountable owners, dates, dependencies, estimates, and approval evidence.
- Keep coordination status distinct from specialist quality, security, and production gates.
- Confirm proposed changes are separated from approved baseline content.
- Confirm acceptance, approval, test, release, and customer decisions are claimed only with evidence.
