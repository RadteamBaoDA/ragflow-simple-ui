# Initiate Project

## Purpose

Produce a controlled project charter and kickoff baseline.

## Task responsibility

Own delivery governance, coordination, customer alignment, and project controls. Do not invent contractual commitments, technical approvals, test evidence, or customer acceptance.

## Core method

1. Resolve **Executive Summary** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
2. Specify **Objectives and Success Measures** as measurable, traceable, unambiguous statements with accountable ownership.
3. Define **Scope and Exclusions** precisely, including exclusions, owners, interfaces, and assumptions.
4. Define **Stakeholders and RACI** precisely, including exclusions, owners, interfaces, and assumptions.
5. Resolve **Delivery Model** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
6. Build **Initial Milestones** from dependencies, capacity, uncertainty, constraints, and reviewable assumptions.
7. Resolve **Governance and Approvals** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
8. Reconcile contradictions and state unresolved evidence, decision, and ownership gaps.

## Quality checks

- Tie commitments to accountable owners, dates, dependencies, estimates, and approval evidence.
- Keep coordination status distinct from specialist quality, security, and production gates.
- Confirm proposed changes are separated from approved baseline content.
- Confirm acceptance, approval, test, release, and customer decisions are claimed only with evidence.
