# Close Project and Capture Lessons

## Purpose

Produce a formal closure and lessons-learned report.

## Task responsibility

Own delivery governance, coordination, customer alignment, and project controls. Do not invent contractual commitments, technical approvals, test evidence, or customer acceptance.

## Core method

1. Resolve **Closure Summary** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
2. Derive **Deliverable Acceptance** from explicit criteria; state conditions, dissent, and decision authority.
3. Resolve **Open Obligations** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
4. Resolve **Handover Status** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
5. Resolve **Lessons Learned** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
6. Resolve **Improvement Actions** using task evidence, applicable constraints, alternatives, and explicit acceptance criteria.
7. Reconcile contradictions and state unresolved evidence, decision, and ownership gaps.

## Quality checks

- Tie commitments to accountable owners, dates, dependencies, estimates, and approval evidence.
- Keep coordination status distinct from specialist quality, security, and production gates.
- Confirm proposed changes are separated from approved baseline content.
- Confirm acceptance, approval, test, release, and customer decisions are claimed only with evidence.
