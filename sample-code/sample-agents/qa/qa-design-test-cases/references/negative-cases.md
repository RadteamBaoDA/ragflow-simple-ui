# Negative test cases

## Use when

Use this variant when invalid, unauthorized, conflicting, or failed inputs are material.

## Task guidance

For **Design Test Cases**, cover validation, permissions, rejected transitions, partial failure, duplicates, sensitive errors, and recovery.

## Decision checks

- Confirm build, environment, data, preconditions, expected result, and observed result.
- Keep passed, failed, blocked, skipped, and not-tested outcomes distinct.
- If multiple references apply, reconcile their constraints explicitly instead of merging incompatible advice.
