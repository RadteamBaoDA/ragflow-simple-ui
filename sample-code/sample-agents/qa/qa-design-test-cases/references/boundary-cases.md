# Boundary test cases

## Use when

Use this variant when limits, ranges, counts, dates, sizes, or state edges are material.

## Task guidance

For **Design Test Cases**, test below, at, and above boundaries plus empty, maximum, precision, overflow, timezone, and transition edges.

## Decision checks

- Confirm build, environment, data, preconditions, expected result, and observed result.
- Keep passed, failed, blocked, skipped, and not-tested outcomes distinct.
- If multiple references apply, reconcile their constraints explicitly instead of merging incompatible advice.
