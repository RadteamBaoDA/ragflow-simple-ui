# Maintainability and operability requirements

## Use when

Use this variant when safe change, supportability, diagnosability, deployment frequency, or operational toil affects solution fitness.

## Task guidance

Define measurable targets for change lead time, rollback time, supported versions, dependency freshness, diagnostic coverage, runbook ownership, automation, and acceptable manual toil. State the component boundary, operating conditions, measurement source, review interval, and accountable engineering or operations owner for each target.

## Decision checks

- Express maintainability and operability as observable outcomes rather than technology preferences.
- Cover upgrade, deprecation, diagnosis, support, and ownership throughout the service lifecycle.
- Resolve trade-offs with availability, security, delivery speed, and cost explicitly.
