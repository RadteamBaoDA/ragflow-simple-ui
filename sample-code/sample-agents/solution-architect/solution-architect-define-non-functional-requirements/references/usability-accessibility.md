# Usability and accessibility requirements

## Use when

Use this variant when user task success, inclusive access, localization, error recovery, or interaction consistency affects acceptance.

## Task guidance

Define target users, assistive technologies, supported locales, representative tasks, environmental constraints, and measurable success criteria. Specify completion rate, error rate, recovery behavior, time-on-task, accessibility standard and level, test method, device or viewport coverage, and accountable design and acceptance owners.

## Decision checks

- Use measurable user outcomes and named standards; avoid subjective terms such as intuitive or user-friendly.
- Cover keyboard, screen-reader, contrast, zoom, motion, language, validation, and failure states when applicable.
- Keep architecture feasibility, UX validation, and formal accessibility conformance as separate evidence states.
