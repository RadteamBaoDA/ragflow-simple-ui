# Data quality and governance requirements

## Use when

Use this variant when correctness, completeness, lineage, retention, residency, privacy, reconciliation, or lifecycle control affects solution acceptance.

## Task guidance

Define critical data elements, quality dimensions, validation rules, tolerated error rates, source of truth, lineage evidence, reconciliation frequency, retention and deletion periods, residency constraints, access ownership, and recovery objectives. Name the measurement query or control, evaluation interval, exception process, and accountable data owner.

## Decision checks

- Separate data quality, security, privacy, compliance, and availability requirements while tracing their dependencies.
- Cover ingestion, transformation, storage, replication, export, archival, correction, and deletion stages.
- Resolve conflicts among retention, minimization, auditability, recovery, and customer contractual obligations.
