# Event-driven architecture

## Use when

Use this variant when asynchronous domain events or decoupled processing are core drivers.

## Task guidance

For **Design Solution Architecture**, define event ownership, schema, ordering, delivery semantics, idempotency, replay, dead-letter handling, and observability.

## Decision checks

- Confirm drivers, alternatives, trade-offs, failure modes, and measurable constraints.
- Identify which decisions need an ADR or accountable approval.
- If multiple references apply, reconcile their constraints explicitly instead of merging incompatible advice.
