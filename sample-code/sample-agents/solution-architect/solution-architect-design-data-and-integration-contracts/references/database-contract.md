# Database contract

## Use when

Use this variant when multiple components depend on persisted schema or data ownership.

## Task guidance

For **Design Data and Integration Contracts**, define owner, entities, keys, constraints, transaction rules, migration compatibility, retention, and access boundary.

## Decision checks

- Confirm drivers, alternatives, trade-offs, failure modes, and measurable constraints.
- Identify which decisions need an ADR or accountable approval.
- If multiple references apply, reconcile their constraints explicitly instead of merging incompatible advice.
