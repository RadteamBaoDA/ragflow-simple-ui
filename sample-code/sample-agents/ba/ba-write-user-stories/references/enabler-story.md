# Enabler story

## Use when

Use this variant when technical or architectural work enables later business value.

## Task guidance

For **Write User Stories**, emphasize state enabled capability, technical outcome, acceptance evidence, dependencies, and impacted future stories.

## Decision checks

- Confirm the source, stakeholder, business rule, and unresolved conflict for each conclusion.
- Keep current state, desired state, proposal, and approved baseline distinct.
- If multiple references apply, reconcile their constraints explicitly instead of merging incompatible advice.
