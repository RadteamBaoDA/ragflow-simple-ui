# Software requirements specification

## Use when

Use this variant when delivery teams need detailed verifiable system behavior.

## Task guidance

For **Write Requirement Specification**, emphasize use uniquely identified functional and non-functional requirements, interfaces, data rules, constraints, and traceability.

## Decision checks

- Confirm the source, stakeholder, business rule, and unresolved conflict for each conclusion.
- Keep current state, desired state, proposal, and approved baseline distinct.
- If multiple references apply, reconcile their constraints explicitly instead of merging incompatible advice.
